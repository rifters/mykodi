Version 2.6.16 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'Remember Where We Left Off' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Fixed resume/bookmark never being saved. CrewMonitor-Worker created a _PlaybackWatcher(xbmc.Player) subclass on a background thread to detect playback start via onAVStarted. Kodi only delivers xbmc.Player callbacks to instances created on the main/service thread, so onAVStarted never fired, the 240s wait always timed out, and bm.reset() was never called. Replaced the callback with a 1s polling loop using isPlayingVideo() which works correctly from any thread.

=====================================================
Version 2.6.15 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'We Measured It' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Measured Real-Debrid's actual 429 rate-limit window using a probe script: RD recovers in ~2.2s. Our hardcoded backoff was 15s (7x too high). Reduced RD_RATE_LIMIT_BACKOFF from 15s to 3s, and raised the initial retry sleep from 2s to 3s (avoids the second 429 hit entirely in most cases). Per 429 event: saves up to 12s of unnecessary waiting.

=====================================================
Version 2.6.14 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'Stop Burning Sources' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Fixed Real-Debrid sources being skipped en-masse during a rate-limit backoff (429). Previously, when RD set a 15s backoff, every subsequent source during that window was immediately discarded (return None). Now, the first source to hit an active backoff sleeps out the remainder, then proceeds — so at most one source causes a brief wait, and all remaining sources flow normally.

Version 2.6.13 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'It's Not Us, It's Them' Release[/B][/COLOR]
=====================================================

This is a Real-Debrid issue — try a different title or check back later.' Only shown when RD actually returned 451 during the session; all other failures still show the standard message.

=====================================================
Version 2.6.12 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'Respect The Law (And The Rate Limiter)' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Fixed 'No stream available' root cause: a DMCA-blocked hash (HTTP 451 from Real-Debrid) causes RD to aggressively rate-limit the very next API call (429). Fix: when RD returns 451, sleep 1 second before moving to the next source, giving RD's limiter time to reset. The 429 cascade is now prevented at the source.

=====================================================
Version 2.6.11 (May 12, 2026) - Hotfix Release - [COLOR cyan][B]The 'Stop Hammering The API' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Fixed 'No stream available' for pack sources caused by Real-Debrid rate limiting (HTTP 429). When the addon tries many pack sources back-to-back, RD now rate-limits after the first few calls. Fix: on 429, sleep 2 seconds and retry once. If still 429, back off for 15 seconds — subsequent sources skip the API call immediately and the next attempt happens after the backoff window expires, giving RD time to recover.
- Applied same 429-retry logic to Premiumize pack resolution.

Version 2.6.7 (May 11, 2026) - Hotfix Release - [COLOR cyan][B]The 'Stop Poking Premiumize' Release[/B][/COLOR]
=====================================================
[COLOR orange]Bug Fixes[/COLOR]
- Fixed Premiumize 429 rate-limit errors during pack resolution: the previous approach called transfer/create for every pack source (20+) to check if content was cached, which PM rate-limits aggressively. Now uses the dedicated cache/check endpoint first (a lightweight hash lookup designed for bulk checking), and only calls transfer/create for the one or two sources that are actually cached.

Version 2.6.6 (May 11, 2026) - Hotfix Release - [COLOR cyan][B]The 'magnets[] Is Not A List' Release[/B][/COLOR]

[COLOR orange]Bug Fixes[/COLOR]

Now handles both dict and list shapes correctly.
